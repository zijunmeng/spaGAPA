# 2026-09-09 Stereo-seq 数据集扩展（GSE293464 + GSE333693）

## 背景：GSE269906 人源升级死锁的确认

- STOmics 官方回复（github.com/STOmics/SAW/issues/268, 2026-02-24）：chip mask 仅在
  实验有效期的云端留存窗口内可下载，旧芯片已从 OSS 清除，"请联合作者"。
- 本地实测（S91, `download_mask` v2.0.0, 2026-09-09）：B02009F6（AD1）与
  B01806B6（Control1）均返回 `No files found for chipSN` —— 对象已删除，
  与 STOmics 账号无关。GSE269906 正式定性为 mask 永久不可获（除非作者提供）。

## 系统性重扫 GEO（新认知：mask 可直接 deposit 在 GEO suppl）

方法（全部程序化，可复现）：
1. esearch db=gds "stereo-seq" entryType=GSE → 75 个系列（2026-09-09 快照）
2. elink gds→sra 逐个探测 → 38 个有 SRA 记录
3. efetch runinfo 过滤 InstrumentModel 含 DNBSEQ → 28 个确认真 Stereo-seq 测序
4. 逐 GSM 列 GEO sample suppl 目录（`geo/samples/GSMnnnnnnn/GSMxxxx/suppl/`），
   从文件名提取芯片 SN（如 `GSM8401816_D02263B1.tissue.gef` → SN=D02263B1）
   并检查是否 deposit 了 `barcodeToPos.h5`

关键发现：**2025–2026 年的 Stereo-seq deposit 开始把 barcodeToPos.h5 直接放进
GEO supplementary**（与我们 GSE263789 WT 的做法一致），完全绕开 STOmics 留存期。

## 执行记录与已验证事项（2026-09-09 17:50 更新）

1. **5 个 mask 全部下载完成并校验**：均为有效 HDF5（bpMatrix_1 稀疏阵，dnbInfo
   25nt barcode），与 GSE263789 WT pilot 已验证可用的 mask 同构。
2. **大鼠参考**：reference-data-rat.tar.gz md5=92dc19ab...cd642 与官方一致，
   已解压至 /s1/SHARE/01_software/SAW_refs/Rattus_norvegicus_index（STAR/fasta/genes）。
3. **SRA 下载**：ODP S3 单传输长连接会衰减（20→1 MB/s，per-transfer 非按 IP），
   方案 = 4 worker 并行 + 每 5 min timeout 重启续传
   （scripts/download_stereo_sra_rotating.sh），实测聚合 47 MB/s，ETA ~4.5h。
4. **fasterq-dump 陷阱（已修复）**：必须传 .sra 文件路径（绝对路径软链），
   传 accession 会走 NCBI 远程且极慢；SRR32936118 实测本地 57s/1.6GB。
5. **读结构验证**：R1=35bp（barcode），R2=100bp（cDNA）——与 GSE269906
   DNBSEQ-T7 Stereo-seq 完全一致，SAW kit="Stereo-seq T FF V1.3"
   sequencing-type="PE75_50+100" 参数沿用。
6. **自动接力**：/tmp/stereo_chain.sh 监听下载完成 → 自动跑两个 fasterq phase。

## 执行问题与修复（2026-09-10 更新）

1. **ENA 大文件续传损坏**：timeout 击杀 + aria2c 分片续传在大文件上产生
   字节完整但 md5 不符的损坏 gz（8 个 `_2` 文件，.aria2 残留为标志）；
   且污染了 GSM8882886/887 两个样本的 merge（D02266C2 SAW 因 FASTQ 记录
   截断报 PARSE ERROR）。修复 = 删除全部 .aria2 残留文件 + 本地 SRA 重转 +
   重并 + 重跑 SAW（GSM8882884 未受影响，保留）。
2. **pigz 拒绝覆盖**：ENA 半成品 .gz 存在时 `pigz` 直接 skip 报错 →
   fasterq phase 链失败；已给两个管线脚本 pigz 加 `-f`。
3. **scAPAtrap outputDir/logf 守卫**：phase 预先 mkdir 的 raw 目录与残留的
   scapatrap_internal.log 都会让 initScAPAtrap 拒绝启动；phase 已改为
   运行前 `rm -rf $raw $rd/scapatrap_internal.log`。
4. **umi_tools RX 标签长度断言（大鼠）**：umi_tools dedup 默认读 RX 而非 UB，
   SAW 原生 RX 长度不齐（21–22）触发 `not all umis are the same length` →
   dedup 0 字节 → 下游 strand BAM 全空。修复 = `scripts/retag_scapatrap_v2.py`
   统一写定长 RX=UB=(UR+'NNNNN')[:5]，两管线已切换 v2。
5. **SAW 输出布局差异**：SAW 8.2.2 输出 BAM 在 `outs/bam/annotated_bam/`
   （大鼠实测），而旧 pilot 为 `STEREO_ANALYSIS_WORKFLOW_PROCESSING/ANNOTATION/`；
   retag phase 已做双路径兼容。
6. **经验**：晚高峰（UTC 下午）ODP/ENA 双双劣化至 <1 MB/s 级，人源 32 runs
   最终以 ODP rotating 8-worker 过夜完成（0 GIVEUP）。
